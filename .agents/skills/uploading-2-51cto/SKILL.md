# 51CTO 博客上传 Skill

将本地 Markdown 文件批量发布到 51CTO 博客平台。

## 使用方式

### 命令行调用

```bash
# 发布前预检（必须在步骤1之前执行）：登录后读取当前个人分类
python3 {skill_path}/scripts/51cto_uploader.py --list-personal-categories

python3 {skill_path}/scripts/51cto_uploader.py "/path/to/article.md"

# 使用预检阶段已确认的分类上传整批文章
python3 {skill_path}/scripts/51cto_uploader.py "/path/to/articles/" --personal-category "人工智能"

# 用户确认后重传保留文件
python3 {skill_path}/scripts/51cto_uploader.py --retry-manifest

# 用户拒绝重传后删除保留文件
python3 {skill_path}/scripts/51cto_uploader.py --discard-manifest
```

## Input

用户需提供要上传的 Markdown 文件路径或包含多个 Markdown 文件的目录路径。

个人分类为可选项。Agent 必须在完整发布流程的步骤1（导出）之前读取实时分类列表并让用户明确选择；同一批文章只允许使用一个值。用户选择“不设置”时，上传脚本不会修改页面的个人分类。

## Output

上传完成后返回结果汇总：

```
==================================================
上传结果汇总
==================================================
成功: X 篇
失败: X 篇
个人分类: 人工智能

成功列表:
  - article_name_1
  - article_name_2

失败列表:
  - article_name: 失败原因

暂时保留的文件:
  - article_name
    路径: /path/to/article.md
    尝试次数: 2
    失败阶段: verify_result
    原因: 最终发布后未检测到明确结果

重试清单: /path/to/tmp/51cto_retry.json
请向用户确认是否重传这些文件；用户拒绝后再删除保留文件。

请访问 51CTO 博客用户中心查看:
https://blog.51cto.com/creative-center/manager
==================================================
```

详细输出示例和日志格式请参考 `references/README.md`。

## 在完整发布流程中的执行时机

当本 Skill 用于“导出 → 优化 → 上传”流程时，必须先在步骤1（备忘录导出）之前完成发布前预检：

1. 执行 `--list-personal-categories`，检查登录并实时读取个人分类。
2. 如果未登录，立即提醒用户在脚本打开的 Selenium Chrome 中完成登录，并等待程序验证成功。
3. 登录成功后把分类列表展示给用户，让用户选择已有分类、新分类名称或不设置。
4. 用户明确确认后，记录该分类，再启动步骤1。

步骤3上传时只使用预检阶段确认的分类，不得再次询问。上传前仍会重新校验登录态；若会话在导出或优化期间失效，必须提示具体原因并停止上传。

## 发布前预检（必须先于步骤1）

使用本 Skill 的预检模式时，必须在步骤1之前完成以下步骤：

1. 执行 `--list-personal-categories`，登录后实时读取 51CTO 当前个人分类。
2. 立即把分类列表展示给用户，并询问本批次要使用哪一个分类。
3. 用户只能选择以下一种结果：
   - 一个已有分类；
   - 输入一个新分类名称；
   - 不设置个人分类。
4. 用户明确答复后，才可以使用 `--personal-category` 启动上传。

如果 `--list-personal-categories` 提示需要登录，Agent 必须立即提醒用户在脚本打开的 Selenium Chrome 中完成登录，并等待程序验证登录成功后再展示分类列表。登录超时、验证码、密码错误或会话失效时，必须反馈具体失败原因并停止整个发布流程，不得在未登录或分类列表无效的情况下继续询问分类，也不得进入步骤1。

禁止等到加载第一篇文章、逐篇选择分类或最终提交前才询问用户。步骤1-3中不得再次询问分类。

## 操作流程

### 发布前预检（步骤1之前）

1. 执行 `--list-personal-categories`，完成登录检查并实时读取个人分类
2. 若提示登录，提醒用户在打开的 Chrome 中完成登录，并等待验证成功
3. 展示分类列表，让用户明确选择已有分类、新分类或不设置
4. 记录用户确认的分类；预检完成后才启动步骤1

### 上传执行（步骤3）

1. 使用预检阶段确认的分类启动上传程序
2. 上传前重新校验登录状态；会话失效时提示具体原因并停止
3. 程序通过发布页标题输入框严格确认登录状态，最多等待 60 秒
4. 如用户选择了分类，上传前实时校验；分类不存在时自动创建并保存验证
5. 自动逐个上传 Markdown 文件，整批使用已确认的分类
6. 对最终提交前的瞬时失败自动重试一次
7. 即时重试后仍失败的文件暂时保留
8. 上传完成后显示结果汇总和重试清单

步骤1-3中不得再次询问个人分类。

## 个人分类选择

- Agent 必须在完整发布流程的步骤1之前向用户确认本批次要使用的个人分类，只接受一个值；不得等到逐篇上传阶段再询问。
- 用户可以明确表示不设置个人分类；此时不得自行推断或任选一个默认值。
- 不得从文章标题、正文、平台文章分类或历史记录中自动推断个人分类。
- 所有文章共用同一个 `--personal-category` 参数值，不允许逐篇变化。
- `--list-personal-categories` 是只读操作：只登录并输出实时分类列表，不上传文件。
- 动态读取分类时如果需要登录，Agent 必须提醒用户在打开的 Chrome 中辅助完成登录，并等待登录验证成功；登录失败时必须先反馈具体原因并停止，不得继续展示或选择分类。
- 登录成功后分类列表读取失败时，Agent 应让用户手动输入分类或选择不设置，不得自行推断。
- 预检完成后，步骤3上传时不得再次询问分类；上传前如发现分类已被删除或改名，脚本会自动创建并验证，失败则停止整批上传。
- 用户输入新分类时，上传程序会在填写文章之前访问 51CTO 分类管理页，点击“添加分类”、填写名称、点击“保存”，并回读确认分类已存在。
- 自动创建或保存失败时，必须停止整批上传并反馈具体原因，不得改用其他分类。
- 脚本在“发布文章”展开的设置面板中定位 `#selfType` 下拉框，点击后按可见文本精确匹配并选择。
- 如果自动创建后下拉框中仍不存在该分类，脚本会在最终提交前失败，并返回当前可选分类列表。
- 重传清单会记录每篇文章使用的个人分类；执行 `--retry-manifest` 时默认沿用。若清单中存在多个个人分类，必须用 `--personal-category` 明确指定一个。

## 即时重试与用户确认机制

- 默认即时重试 `1` 次，单篇最多自动尝试 `2` 次。
- 只对最终提交前的可恢复失败执行即时重试。
- 已经点击最终发布但无法确认结果时，禁止自动重试，避免重复发布。
- 即时重试仍失败后，程序保留本地文件并写入 `tmp/51cto_retry.json`。
- Agent 必须向用户说明失败原因、尝试次数、失败阶段和保留文件路径。
- Agent 必须询问用户是否重传保留文件。
- 用户同意时执行 `--retry-manifest`。
- 用户拒绝时执行 `--discard-manifest` 删除保留文件。
- 用户未回复时不得删除文件。
- 用户确认重传后仍失败时，文件继续保留，并再次反馈和询问。
- Agent 不得自行使用 `input()` 或假设用户同意删除。

## 兼容性

- **操作系统**：仅支持 macOS 和 Windows（需要 Chrome 浏览器）
- **Python**：Python 3.x
- **依赖**：`pip install -r requirements.txt`
- **浏览器**：本地 Google Chrome；ChromeDriver 由 Selenium Manager 自动获取

## 注意事项

- 首次运行需要网络下载匹配的 ChromeDriver，网络超时限制为 120 秒
- 发布前预检（步骤1之前）请先在浏览器中登录 51CTO 博客；步骤3上传前会再次校验登录态
- 登录失败时会反馈具体原因，例如登录超时、密码错误、验证码、会话失效、浏览器关闭或发布页不可用
- 启动 Chrome 前会检查 SeleniumProfile 和 Selenium 缓存的写权限，并在无活动 Chrome 时清理陈旧 `DevToolsActivePort`/Singleton 锁文件
- 在 Codex 沙箱中运行上传任务时，必须主动申请 SeleniumProfile 和 Selenium 缓存所在外部目录的写权限
- 权限不足会返回 `browser_permission_required`，不会误报为未登录或 Profile 被占用
- 程序检测到未登录状态时会终止运行并提示
- 批量上传时文件逐个加载，避免内存溢出
- 登录状态通过 Chrome 用户数据目录持久化
- 上传成功后会删除本地文件
- 即时重试失败后会暂时保留文件，必须由用户决定重传还是删除
- 已有个人分类名称必须与 51CTO 页面中的文本完全一致；新分类由用户明确输入后自动创建
